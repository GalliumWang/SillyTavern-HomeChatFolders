## Chrome 界面验证（模拟酒馆接口）

开发页使用 137 个模拟会话，包含三个角色、一个群组和 HTML 形状的测试标题。与真实酒馆和真实聊天完全分离。

已观察到的最终结果：

- 原生 `.welcomeRecent` 的计算样式为 `display:none`，替代界面在相同首页容器中出现。
- 最近目录自动补全为 137 条，每页渲染 50 条。
- 新建顶层文件夹、新建子文件夹、默认选择当前父文件夹正常。
- 把当前页 50 条跨角色及群聊会话批量移动到“进行中”，未分类计数降为 87。
- 名称多关键词搜索返回预期的角色与会话。
- 刷新后保留新建的文件夹、子级结构和 50 条分类。
- 单角色和群聊打开后均显示正确的角色/群组及目标会话名；返回首页能重新挂载。
- 模拟 HTTP 503 时显示错误，137 条已读取目录和 50 条分类保持不变。
- 点击“恢复原列表”后替代节点数为 0，原生列表恢复 `display:block`；设置中重新启用有效。
- 390×844 窄屏测试：文件夹区域与列表改为上下排列，页面宽度与视口一致，无横向溢出。测试后恢复了正常视口。
- HTML 形状标题显示为文本，没有变成标题内的图片元素。

导出下载事件的浏览器自动化等待超时，未将其记为界面验证通过；导入/导出的数据格式及往返正确性由自动测试验证。
